Rate limits

The Tidewater API limits how many requests each API key can make. Limits are applied per key, not per IP address.

Response headers

Every response includes X-RateLimit-Remaining, the number of requests left in the current window, and X-RateLimit-Reset, the Unix time at which the window resets.

When you exceed a limit

The API returns HTTP 429 Too Many Requests with a Retry-After header giving the number of seconds to wait. Clients should back off exponentially, starting at the Retry-After value and doubling up to a maximum of 64 seconds.

async function withRetry(fn, attempt = 0) {
  const res = await fn();
  if (res.status !== 429 || attempt >= 6) return res;
  const wait = Math.min(64, Number(res.headers.get("Retry-After")) * 2 ** attempt);
  await new Promise((r) => setTimeout(r, wait * 1000));
  return withRetry(fn, attempt + 1);
}

Streaming endpoints count once per stream, when the stream opens. A stream that stays open does not consume further requests.
